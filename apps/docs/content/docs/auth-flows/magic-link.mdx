# Magic Link (Passwordless)

## Flow

1. Client sends `POST /api/auth/magic-link` with the user's email
2. Server generates a cryptographically random token (32 bytes), stores it hashed in Redis with 15-minute TTL
3. Server sends an email with `https://app.sentry.scrolloop.com/u/magic-link?token=<token>`
4. User clicks the link → client sends `POST /api/auth/magic-link/verify` with the token
5. Server verifies the token, issues a full session + JWT

## API

```http
POST /api/auth/magic-link
Content-Type: application/json
x-tenant-id: acme

{
  "email": "user@example.com"
}

→ 202 Accepted
{
  "message": "Magic link sent to your email"
}
```

```http
POST /api/auth/magic-link/verify
Content-Type: application/json
x-tenant-id: acme

{
  "token": "a3f9c2d1..."
}

→ 200 OK
{
  "accessToken": "eyJ...",
  "refreshToken": "...",
  "user": { "id": "...", "email": "user@example.com" }
}
```

## Security properties

- Token is **single-use** — consumed on first successful verify
- 15-minute TTL
- Token is stored as a SHA-256 hash in Redis; the plaintext is never persisted
- Rate-limited: 3 magic link requests per 10 minutes per email
