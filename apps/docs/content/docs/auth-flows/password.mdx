# Password Login

## Flow

```
Client                          auth-service
  │                                  │
  │── POST /api/auth/login ─────────▶│
  │   { email, password }            │
  │                                  ├─ Brute-force check (Redis)
  │                                  │  5 attempts / 15 min / IP+email
  │                                  ├─ Fetch user by email
  │                                  ├─ Argon2id verify password
  │                                  │
  │                          [MFA enrolled?]
  │                             yes │           no │
  │                                  │              ├─ Create session (DB + Redis)
  │                                  │              ├─ Sign RS256 JWT (15 min)
  │                                  │              ├─ Issue refresh token (7 days)
  │◀──────────────────────── 200 ────┤              └─ Return tokens + user
  │   { mfaPendingToken }            │
  │                                  │
  │── POST /api/auth/mfa/verify ────▶│
  │   { token, code, method }        ├─ Verify TOTP / backup / WebAuthn
  │                                  ├─ Create session
  │◀──────────────────────── 200 ────┤
  │   { accessToken, refreshToken }  │
```

## Brute-force protection

- Sliding window: **5 failed attempts per 15 minutes** per `IP + email` combination
- Counter stored in Redis with automatic expiry
- After limit exceeded: `429 Too Many Requests` with `Retry-After` header
- Successful login resets the counter

## Token rotation

On every token refresh (`POST /api/auth/refresh`):

1. Old refresh token is **immediately revoked**
2. New refresh token is issued with a new family ID
3. If the same refresh token is used twice → entire family is revoked (reuse detection)

## Error responses

| Status | Reason |
|--------|--------|
| `401` | Invalid email or password |
| `403` | Account disabled |
| `429` | Too many failed attempts |
