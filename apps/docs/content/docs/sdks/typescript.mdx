# TypeScript SDK

Package: `@scrolloop/sdk`

## Installation

```bash
npm install @scrolloop/sdk
# or
yarn add @scrolloop/sdk
```

## Setup

```ts
import { ScrolloopSentry } from '@scrolloop/sdk';

const sentry = new ScrolloopSentry({
  domain: 'acme.sentry.scrolloop.com',
  clientId: 'your-oauth-client-id',
});
```

## Authentication

```ts
// Password login
const { accessToken, user } = await sentry.auth.loginWithPassword({
  email: 'user@example.com',
  password: 'secret',
});

// Magic link
await sentry.auth.sendMagicLink({ email: 'user@example.com' });

// Verify magic link token (from URL)
const { accessToken } = await sentry.auth.verifyMagicLink({ token: urlToken });

// Logout
await sentry.auth.logout();

// Refresh tokens
const { accessToken } = await sentry.auth.refresh();
```

## User

```ts
// Get current user
const user = await sentry.users.getMe();

// Update profile
await sentry.users.updateMe({ firstName: 'Ada' });

// Change password
await sentry.users.changePassword({
  currentPassword: 'old',
  newPassword: 'new-strong-pass',
});

// List active sessions
const sessions = await sentry.users.getSessions();

// Revoke a session
await sentry.users.revokeSession(sessionId);
```

## RBAC

```ts
// Check if current user has a permission
const canDelete = await sentry.rbac.can('users:delete');

// Get current user's roles
const roles = await sentry.rbac.getRoles();
```

## Token management

The SDK stores the access token in memory and the refresh token in a secure cookie. Tokens are refreshed automatically before they expire.

```ts
// Get current access token (auto-refreshes if needed)
const token = await sentry.getAccessToken();

// Verify a token using the JWKS endpoint
const payload = await sentry.verifyToken(token);
```

## Errors

Failed API calls throw `SentryApiError`, parsed from the API's `application/problem+json`
response. It extends `AuthError`, so existing `catch` blocks and `instanceof AuthError` checks keep working.
`error.message` is `detail ?? title`.

| Property | Type | Description |
|----------|------|-------------|
| `code` | string | Stable machine code, for example `AUTH_INVALID_CREDENTIALS` (see the [API error codes](/docs/api#error-codes)) |
| `status` | number | HTTP status |
| `title` | string | Short summary |
| `detail` | string \| undefined | User-safe explanation |
| `requestId` | string \| undefined | Quote when contacting support |
| `fieldErrors` | `{ field, message }[]` | Populated for `VALIDATION_FAILED` (empty otherwise) |
| `retryAfterSeconds` | number \| undefined | Populated for `RATE_LIMITED` |

```ts
import { SentryApiError } from "@scrolloop/sdk";

try {
  await sentry.login({ email, password });
} catch (err) {
  if (err instanceof SentryApiError) {
    switch (err.code) {
      case "VALIDATION_FAILED":
        showFieldErrors(err.fieldErrors);
        break;
      case "RATE_LIMITED":
        showMessage(`Try again in ${err.retryAfterSeconds ?? 60}s`);
        break;
      default:
        showMessage(`${err.message} (reference ${err.requestId})`);
    }
  }
}
```

Responses from older API versions (`{ statusCode, message }` or `{ error: { code, message } }`) and
non-JSON gateway errors are still converted into a `SentryApiError` with a best-effort `code`.
