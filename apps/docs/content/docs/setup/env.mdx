# Environment Variables

The auth-service validates its environment at boot and refuses to start if a required value is
missing or malformed. The authoritative contract is
`apps/auth-service/src/config/env.validation.ts`; `apps/auth-service/.env.example` mirrors it.

## Required

| Variable | Format | Purpose |
|---|---|---|
| `ISSUER_BASE_URL` | URL | Externally reachable URL of the auth-service; roots discovery endpoints |
| `FRONTEND_URL` | URL | Base URL used in email links |
| `CORS_ORIGINS` | comma list | Static CORS allow-list (per-tenant origins are added from the DB) |
| `JWT_SECRET` | ≥ 32 chars | HS256 secret for short-lived internal tokens (`openssl rand -hex 32`) |
| `KEYRING_MASTER_KEY` | base64, 44 chars | Encrypts RSA private keys at rest (`openssl rand -base64 32`) |
| `SESSION_SECRET` | ≥ 32 chars | Signs the OAuth handshake session cookie (`openssl rand -hex 32`) |
| `TOKEN_ENCRYPTION_KEY` | 64 hex | Encrypts stored third-party OAuth tokens. Required in production (`openssl rand -hex 32`) |
| `DB_URL` | postgres URL | Database. `DATABASE_URL` or `DATABASE_HOST` + `DATABASE_PORT/USER/PASSWORD/NAME` also accepted |

## Tokens & identity

| Variable | Default | Purpose |
|---|---|---|
| `JWT_ISSUER` | `https://sentry.scrolloop.com` | `iss` claim; also the discovery `issuer` |
| `SESSION_TTL` | `604800` | Server-side session lifetime (seconds) |

## Platform & tenancy

| Variable | Default | Purpose |
|---|---|---|
| `SENTRY_PLATFORM_NAME` | `Scrolloop Sentry` | Display name |
| `SENTRY_PLATFORM_SLUG` | `sentry` | Platform tenant slug |
| `SENTRY_PLATFORM_DOMAIN` | — | Enables subdomain tenancy (`acme.<domain>`) |
| `ALLOW_TENANT_ID_HEADER` | `false` | Accept `X-Tenant-ID` in production |
| `COOKIE_DOMAIN` | — | Share auth cookies across tenant subdomains (e.g. `.sentry.scrolloop.com`) |
| `TRUST_PROXY` | — | Proxy hops/subnets to trust. **Required behind a load balancer** |

## Database

| Variable | Default | Purpose |
|---|---|---|
| `DB_SSL` | `false` | Enable TLS |
| `DB_SSL_CA` | — | CA (PEM or base64 PEM) to verify the server — recommended in production |
| `DB_SSL_REJECT_UNAUTHORIZED` | `false` | Verify against the system CA bundle |
| `DB_LOGGING` | `false` | Log SQL |
| `DATABASE_POOL_MAX` / `DATABASE_POOL_MIN` | `20` / `2` | Pool size |

## Redis

`REDIS_HOST` (`localhost`), `REDIS_PORT` (`6379`), `REDIS_USERNAME`, `REDIS_PASSWORD`,
`REDIS_DB` (`0`), `REDIS_KEY_PREFIX` (`sentry`).

## Email

Provider is auto-detected: AWS SES if `AWS_SES_ACCESS_KEY_ID` and `AWS_SES_SECRET_ACCESS_KEY` are
set, otherwise SMTP if `SMTP_HOST` is set, otherwise emails are logged (development).

`EMAIL_FROM`, `EMAIL_FROM_NAME`, `EMAIL_REPLY_TO`, `SUPPORT_EMAIL`, `SMTP_HOST`, `SMTP_PORT`,
`SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS`, `AWS_SES_REGION`, `AWS_SES_ACCESS_KEY_ID`,
`AWS_SES_SECRET_ACCESS_KEY`.

## WebAuthn

`WEBAUTHN_RP_ID` (`localhost`), `WEBAUTHN_ORIGIN` (`http://localhost:3000`).

## Platform social login (optional)

`INTERNAL_{GOOGLE,GITHUB,MICROSOFT}_{CLIENT_ID,CLIENT_SECRET,CALLBACK_URL}`.

## Other URLs

`PORTAL_URL`, `INTERNAL_PORTAL_URL`, `AUTH_SERVICE_URL`, `PUBLIC_BASE_URL` (base for uploaded
assets), `ADMIN_PORTAL_ORIGIN` (allowed during first-run bootstrap), `UPLOAD_DIR`.

## Development & seeding only

| Variable | Purpose |
|---|---|
| `DISABLE_RATE_LIMIT` | Disable rate limits; ignored unless `NODE_ENV=development` |
| `SEED_SUPERADMIN_EMAIL` / `SEED_SUPERADMIN_PASSWORD` | Create a superadmin during `db:seed` |
| `SEED_EXAMPLE_CLIENTS` | Seed the demo third-party OAuth client |
| `SENTRY_SETUP_LOG_DIR` | Where the first-run setup token is written (default `~/.sentry`) |
