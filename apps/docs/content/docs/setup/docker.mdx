# Deployment

## Local infrastructure

`docker-compose.yml` at the repository root starts only the backing services:

| Service | Image | Ports |
|---|---|---|
| Postgres | `postgres:16-alpine` | 5432 |
| Redis | `redis:7-alpine` | 6379 |
| Mailpit | `axllent/mailpit` | 1025 (SMTP), 8025 (UI) |

```bash
docker compose up -d       # start
docker compose down -v     # stop and wipe data
```

## Production checklist

Container images and a Helm chart are on the roadmap. Until then, run the auth-service with
`yarn build && yarn start:prod` behind a TLS-terminating proxy, and ensure:

- `NODE_ENV=production`
- `TRUST_PROXY` matches your proxy topology (otherwise rate limits key on the proxy IP)
- `DB_SSL=true` with `DB_SSL_CA` set
- secrets (`JWT_SECRET`, `SESSION_SECRET`, `KEYRING_MASTER_KEY`, `TOKEN_ENCRYPTION_KEY`) come
  from a secret manager
- `COOKIE_DOMAIN` and `SENTRY_PLATFORM_DOMAIN` are set for subdomain tenancy
- migrations run before the new version starts: `yarn db:migrate`
- probes: liveness `GET /health`, readiness `GET /health/ready`
- `SEED_*` and `DISABLE_RATE_LIMIT` are never set
