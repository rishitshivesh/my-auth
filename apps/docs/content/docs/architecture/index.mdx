# Architecture Overview

## Monorepo structure

```
/
├── apps/
│   ├── auth-service/     NestJS 11 — auth server, all API endpoints
│   ├── admin-portal/     Next.js 16 — admin UI + user-facing auth flows
│   └── docs/             This documentation site (Fumadocs + Next.js)
├── packages/
│   ├── database/         TypeORM entities, migrations, connection builder
│   ├── security/         Argon2id, AES-256-GCM, rate limiter
│   ├── sdk-typescript/   @scrolloop/sdk — browser + React + Next.js
│   ├── admin-client/     Admin API client
│   ├── sentry-config/    SDK configuration
│   ├── sentry-types/     Shared types
│   └── ui/, shared/      UI kit and shared utilities
└── docs/                 Internal engineering docs (architecture, security, ADRs)
```

## Services

### auth-service (port 4000)

The core auth server. Responsibilities:

- All authentication flows (password, magic link, social OAuth, WebAuthn)
- JWT issuance (RS256 with persisted, encrypted key pairs)
- JWKS endpoint and OIDC discovery
- OAuth 2.0 / OIDC authorization server
- RBAC + policy engine
- Session management (PostgreSQL + Redis dual-layer)
- Multi-tenant schema management
- User management API
- Audit logging

**Stack:** NestJS 11, TypeORM, PostgreSQL 16, Redis, Argon2id, AES-256-GCM, BullMQ, Pino

### admin-portal (port 3000)

The frontend application. Serves two audiences:

1. **Platform operators** — superadmin dashboard at `/dashboard`
2. **Tenant admins** — workspace dashboards at `/t/{slug}/dashboard`
3. **End users** — auth flows at `/u/login`, `/u/signup`, `/mfa/enroll`

**Stack:** Next.js 16 App Router, TanStack Query v5, Tailwind CSS v4, shadcn/ui

## Request lifecycle

```
Browser
  │
  ▼
Next.js middleware (middleware.ts)
  │  ├─ Check sentry-initialized cookie / fetch /superadmin/initialized
  │  ├─ Redirect to /setup if uninitialized
  │  ├─ Subdomain routing (acme.sentry.scrolloop.com → /t/acme/...)
  │  └─ JWT claim checks for superadmin / tenant routes
  │
  ▼
Next.js page / server component
  │
  ▼
auth-service API (http://localhost:4000)
  │
  ├─ TenantResolverMiddleware
  │    Resolves tenant from: custom domain → subdomain → X-Tenant-ID header
  │    Excluded for: /superadmin/*, /tenants/register, /tenants/slug-check
  │
  ├─ TenantSchemaMiddleware
  │    SET search_path TO "fk_{slug}", public
  │    Stored in AsyncLocalStorage via TenantContextService
  │    Excluded for: same routes as above
  │
  ├─ Guards
  │    JwtAuthGuard → validates RS256 JWT
  │    TenantBindingGuard → validates JWT tid matches req.tenant
  │    RateLimitGuard → Redis sliding window
  │
  ├─ Controller / Service
  │    TenantAwareRepository → reads QueryRunner from TenantContextService
  │
  └─ Response
       search_path reset to public
       QueryRunner released to pool
```

## Database schema model

```
public schema (platform-level)
  tenants           All workspaces
  key_pairs         Per-tenant RSA signing keys
  admin_users       Superadmin accounts

fk_{slug} schema (per-tenant, created on workspace registration)
  users             Workspace users
  sessions          Active sessions
  refresh_tokens    JWT refresh tokens
  mfa_configs       TOTP / WebAuthn configs
  backup_codes      MFA backup codes
  oauth_clients     Registered OAuth applications
  oauth_tokens      Issued tokens (AES-256-GCM encrypted)
  webauthn_credentials
  roles             Custom and system roles
  permissions       Permission definitions
  user_roles        Role assignments
  policies          IAM-style policy documents
  groups            User groups
  audit_logs        Immutable audit trail
  security_events   Security-relevant events
  user_invites      Pending invitations
  password_history  Previous password hashes (prevent reuse)
  tenant_password_policy
```
