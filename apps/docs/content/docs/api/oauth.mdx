# OAuth 2.0 / OIDC API

Sentry is a full OAuth 2.0 authorization server + OIDC provider.

---

## Discovery

### GET /.well-known/openid-configuration

OIDC discovery document. No auth required.

```json
{
  "issuer": "https://sentry.scrolloop.com/t/acme",
  "authorization_endpoint": "https://sentry.scrolloop.com/oauth/authorize",
  "token_endpoint": "https://sentry.scrolloop.com/oauth/token",
  "userinfo_endpoint": "https://sentry.scrolloop.com/oauth/userinfo",
  "end_session_endpoint": "https://sentry.scrolloop.com/oauth/end_session",
  "jwks_uri": "https://sentry.scrolloop.com/.well-known/jwks.json",
  "response_types_supported": ["code"],
  "grant_types_supported": ["authorization_code", "client_credentials", "refresh_token"],
  "subject_types_supported": ["public"],
  "id_token_signing_alg_values_supported": ["RS256"],
  "scopes_supported": ["openid", "profile", "email", "offline_access"]
}
```

### GET /.well-known/jwks.json

Public keys for JWT verification. No auth required.

```json
{
  "keys": [
    {
      "kty": "RSA",
      "use": "sig",
      "alg": "RS256",
      "kid": "key-id",
      "n": "...",
      "e": "AQAB"
    }
  ]
}
```

## Authorization Code + PKCE

### GET /oauth/authorize

Start the authorization flow. Redirect the user's browser here.

```
GET /oauth/authorize
  ?client_id=your-client-id
  &redirect_uri=https%3A%2F%2Fapp.example.com%2Fcallback
  &response_type=code
  &scope=openid+profile+email+offline_access
  &state=random-csrf-value
  &code_challenge=S256-hash-of-verifier
  &code_challenge_method=S256
```

PKCE is **required** for public clients (SPAs, mobile apps).

Generate a code verifier and challenge:

```ts
const verifier = crypto.randomBytes(32).toString('base64url');
const challenge = crypto.createHash('sha256').update(verifier).digest('base64url');
```

Optional parameters: `nonce`, `prompt`, `max_age`.

| Situation | Result |
|---|---|
| Invalid `client_id`, `redirect_uri`, scope or PKCE | `400` JSON `invalid_request` (never redirected) |
| No valid session cookie | `302` to `{FRONTEND_URL}/u/login?tenant={slug}&continue=/oauth/authorize?...` |
| Consent required | `302` to `{FRONTEND_URL}/u/consent?transaction_id=...` |
| Otherwise | `302` to `redirect_uri?code=...&state=...` |

The user is resolved from the access-token session cookie, bound to the request tenant.
`continue` is always a same-origin relative `/oauth/authorize` URL rebuilt from validated
parameters; the login UI must refuse any other value.

- `prompt=none`: never shows UI; returns `error=login_required` or `error=consent_required` to the `redirect_uri`. Must be used alone.
- `prompt=login`: forces re-authentication (the `continue` URL carries an internal `auth_after` marker).
- `prompt=consent`: always shows the consent screen.
- `max_age`: a session whose login is older than this many seconds re-authenticates.
- First-party clients, and clients with an unexpired consent covering the scopes, skip consent.

The code is bound to the client, `redirect_uri`, PKCE challenge, nonce, user, tenant, session id,
`auth_time` and `amr`. The ID token carries `sid`, `auth_time`, `amr` and `acr`
(`1` single factor, `2` with MFA). `amr` and `auth_time` come from the login that created the session and are stored on it, so they
survive token refresh: password `["pwd"]`, password + TOTP `["pwd","otp","totp","mfa"]`, password +
backup code `["pwd","backup_code","mfa"]`, passkey `["hwk","webauthn"]`, magic link `["magic_link"]`,
social sign-in `["social"]`. Sessions created before this was recorded report `["pwd"]`.

### Consent

`GET /oauth/consent/{transaction_id}` (session cookie) returns the client, scopes and a `csrf_token`.
`POST /oauth/consent` with `{ "transaction_id", "csrf_token", "decision": "allow"|"deny", "remember"? }`
returns `{ "redirect_to": "..." }` (code on allow, `access_denied` on deny). The transaction is
single-use, expires after 10 minutes and is bound to the user's session.

### GET|POST /oauth/end_session

OIDC RP-Initiated Logout. Parameters: `id_token_hint`, `post_logout_redirect_uri`, `state`, `client_id`.

- `id_token_hint` must be an ID token we issued (expiry ignored). Its session and the OAuth tokens
  issued from it are revoked, auth cookies are cleared and the audit log records a logout.
- `post_logout_redirect_uri` must exactly match a URI registered on the client (and requires a hint), otherwise `400`.
- Without a hint nothing is ended; the browser is sent to `{FRONTEND_URL}/u/logout` to confirm.

### POST /oauth/token (authorization code)

Exchange the authorization code for tokens.

```http
POST /oauth/token
Content-Type: application/x-www-form-urlencoded

grant_type=authorization_code
&code=<code-from-redirect>
&redirect_uri=https://app.example.com/callback
&client_id=your-client-id
&client_secret=your-client-secret
&code_verifier=<original-verifier>
```

**Response `200`:**

```json
{
  "access_token": "eyJ...",
  "refresh_token": "...",
  "id_token": "eyJ...",
  "token_type": "Bearer",
  "expires_in": 900
}
```

## Client Credentials

For server-to-server / M2M flows.

```http
POST /oauth/token
Content-Type: application/x-www-form-urlencoded

grant_type=client_credentials
&client_id=your-client-id
&client_secret=your-client-secret
&scope=users:read roles:read
```

## Token Management

### POST /oauth/revoke

Revoke an access or refresh token.

```http
POST /oauth/revoke
Content-Type: application/x-www-form-urlencoded

token=<token>
&token_type_hint=refresh_token
```

### POST /oauth/introspect

Check whether a token is active.

```http
POST /oauth/introspect
Content-Type: application/x-www-form-urlencoded
Authorization: Basic <client_id:client_secret base64>

token=<access-token>
```

**Response `200`:**

```json
{
  "active": true,
  "sub": "user-uuid",
  "client_id": "client-uuid",
  "scope": "openid profile",
  "exp": 1700000900
}
```

## UserInfo

### GET /oauth/userinfo

Fetch the authenticated user's profile.

```http
GET /oauth/userinfo
Authorization: Bearer <access-token>
```

**Response `200`:**

```json
{
  "sub": "user-uuid",
  "email": "user@example.com",
  "name": "Ada Lovelace",
  "given_name": "Ada",
  "family_name": "Lovelace",
  "picture": "https://...",
  "email_verified": true
}
```
